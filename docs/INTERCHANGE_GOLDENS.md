# R1l — Closed-contour CAD interchange and golden regression matrix

CarveFoundry now has **fixed, independently hand-authored ASCII input
fixtures**, not generated by its own exporter, in the native Rust core:

- [capsule_external.svg](../crates/core/tests/fixtures/capsule_external.svg):
  200 × 200 mm SVG, explicitly traced line / 180° arc / line /
  180° arc, with Y-down SVG coordinates.
- [capsule_external.dxf](../crates/core/tests/fixtures/capsule_external.dxf):
  ASCII DXF with `$INSUNITS=4` (mm) and a closed four-vertex
  `LWPOLYLINE` containing two mathematically exact semicircular
  bulges of +1. This fixture has no CarveFoundry-specific XDATA.

The fixtures describe the **same analytic CAD contour**: the straight
runs span (40,40)–(100,40) and (100,80)–(40,80); the right semicircle
is centered at (100,60), and the left is centered at (40,60), both
radius 20 mm and counterclockwise.

## Automated regression contract

The core integration test `tests/interchange_goldens.rs`:

1. Parses both independently authored files and compares physical XY
   node locations, genuine line/arc types, circle centers, segment
   counts, traversal winding and closed/open status.
2. Validates globally that the source contour has no self-intersecting
   segments or coincident-circle overlaps.
3. Exports either source as SVG and DXF and imports both again; also
   crosses SVG → DXF and DXF → SVG without flattening the original
   curves. It compares actual geometric values, rather than exact
   output strings, numeric text formatting, source node IDs or
   metadata not shared by generic interchange.
4. Offsets the closed capsule +3 mm and -2 mm. Both keep genuine
   circular sectors with expected radii 23 mm / 18 mm, exact bounds
   and no new self-crossings. Inward radius collapse is rejected.
5. Tests an independently authored **reentrant L-shaped closed profile**,
   with exactly five convex round joins outside and one at the inward
   concave corner; asserts all final arcs remain exact and re-import
   across both formats.
6. Checks a remote crossing on an **open straight-only contour**. The
   traditional straight-offset code now validates both source and
   result with the same full-chain analytic guard as curved offsets;
   a crossing rejects without mutating source.

This is test-based interchange compatibility with two hand-authored
**supported subset** fixtures, not a certification that any external
CAD application will preserve all metadata, all SVG command forms,
all unsupported DXF entities or all compound/hole design semantics.
